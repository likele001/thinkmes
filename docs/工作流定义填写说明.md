# 工作流系统使用说明

本文档说明工作流系统的作用、配置方法和使用流程，帮助你正确配置和使用 MES 工作流。

## 🎯 工作流系统概述

工作流系统是一个**通用的审批流程管理框架**，用于管理业务数据的审批流转过程。简单来说，就是为您的业务数据（如MES订单）配置审批流程。

### 核心功能

- 📋 **状态管理**：定义业务数据的不同状态（草稿、待审核、已通过等）
- 🔄 **流程流转**：设置状态之间的转换规则
- 👥 **审批配置**：指定每个节点的审批人
- 📊 **流程可视化**：查看流程进度和历史记录

### 与MES系统的关联

MES订单已经集成了工作流系统，订单创建时会自动启动工作流：

```php
// MES订单创建时自动启动工作流
protected function startOrderWorkflow(int $orderId, string $title): void
{
    $service = new WorkflowService($tenantId, $auth->id, $auth->username);
    $service->startWorkflow('mes_order', $orderId, $title);
}
```

## 表单字段说明

### 1. 工作流名称

- 字段名：`row[name]`
- 含义：流程的中文名称，用于后台界面显示。
- 示例：`订单审批流程`

### 2. 工作流标识

- 字段名：`row[code]`
- 含义：唯一标识符，必须为字母数字组合。
- 作用：系统内部识别该工作流，建议使用英文下划线风格。
- 示例：`order_approval`

### 3. 关联表名

- 字段名：`row[table_name]`
- 含义：该工作流对应的业务表名。
- 注意：必须选择实际数据库表名，否则工作流无法绑定业务数据。不能随意写“order”、“worksheet”这类非表名。
- MES系统常见示例：`mes_order`、`mes_purchase`、`mes_production`、`mes_inventory`
- 选择建议：如果要为订单审批建流程，优先选 `mes_order`；如果要为采购建流程，选 `mes_purchase`。
- 页面说明：该字段已经改为下拉选择，系统会自动提供可选表名。

### 4. 标题字段

- 字段名：`row[title_field]`
- 含义：工作流实例显示标题所使用的业务表字段。
- 作用：当实例列表或详情显示时，会用这个字段的值作为标题。
- 注意：该字段必须是关联表中存在的字段名，不能随意写。
- 常见示例：`order_no`、`order_name`、`name`、`contract_no`
- 选择建议：如果关联表是 `mes_order`，通常填 `order_no`；如果关联表是采购单，可填 `purchase_no` 或 `name`。
- 页面说明：该字段已经改为下拉选择，系统会根据所选关联表自动显示常用标题字段选项。标题字段会在选择关联表后启用，避免用户未选表名就填写。

### 5. 初始状态

- 字段名：`row[initial_state]`
- 含义：工作流刚启动时的默认状态标识。
- 注意：该值必须与下面“流程状态”区块中某个状态的 `状态标识` 一致。
- 填写方式：先在“流程状态”区域添加至少一个状态，然后从下拉框中选择初始状态；不能手工输入随机值。
- 建议：优先使用 `pending`、`draft`、`waiting` 之类的稳定标识，避免使用中文。
- 示例：`pending`

### 6. 状态和操作名称不能乱写

- `状态标识` 是系统内部状态编码，必须唯一、明确、稳定。
- `状态名称` 是界面显示文本，可以写成中文，例如 `待审核`、`已审批`。
- `操作名称` 是按钮文字，建议写成 `提交审批`、`审批通过`、`驳回` 等可理解的动作。
- 页面已改成固定可选列表，`状态标识` 和 `操作名称` 需从候选项中选择，不要随意手工输入。
- 源状态/目标状态一定要填写已定义的 `状态标识`，不能写状态名称。
- 例如：`pending` -> `approved` 的 `操作名称` 可以是 `审批通过`；`pending` -> `rejected` 的 `操作名称` 可以是 `驳回`。

### 7. 描述

- 字段名：`row[description]`
- 含义：可选字段，用于说明该工作流的用途、业务场景。
- 示例：`用于 MES 订单审批流程`

### 8. 状态

- 字段名：`row[status]`
- 含义：工作流是否启用。
- 填写方式：选择 `启用` 或 `禁用`。
- 建议：先保存后再配置流程状态和规则。

## 流程状态（状态定义）

这个区块用于定义工作流的“状态节点”。每个工作流至少需要一个状态。

每个状态包含：

- `状态标识`：系统内部使用的状态码，如 `pending`、`approved`。
- `状态名称`：前端显示名称，如 `待审核`、`已审核`。
- `排序`：显示顺序，数字越小越靠前。
- `类型`：用于标记开始、结束或普通状态。

填写建议：

- 至少定义一个 `开始` 类型状态，并且该状态的 `状态标识` 与“初始状态”一致。
- 如果工作流有成功结束点，增加一个 `结束` 类型状态。
- `普通` 类型适用于中间节点。

示例：

- 状态标识：`pending`，状态名称：`待审核`，类型：`开始`
- 状态标识：`approved`，状态名称：`已审批`，类型：`普通`
- 状态标识：`rejected`，状态名称：`已拒绝`，类型：`结束`

## 流转规则

该区块定义状态之间的转换关系。

每条规则包含：

- `源状态`：当前状态。
- `目标状态`：转换后的状态。
- `操作名称`：如果在操作按钮上显示时，使用这个名称。

填写建议：

- 源状态、目标状态必须是上面已定义的状态 `状态标识`。
- 一条 `源状态` 可以对应多个不同的 `目标状态`，用于实现“转审批/驳回”等分支。
- `操作名称` 应该清晰描述这一步动作，如 `提交审批`、`审批通过`、`驳回`

示例：

- 源状态：`pending`，目标状态：`approved`，操作名称：`审批通过`
- 源状态：`pending`，目标状态：`rejected`，操作名称：`驳回`

## 常见填写场景

### 订单审批示例

1. 工作流名称：`订单审批流程`
2. 工作流标识：`order_approval`
3. 关联表名：`mes_order`
4. 标题字段：`order_no`
5. 初始状态：`pending`

状态定义：

- `pending` / `待审核` / 类型：`开始`
- `approved` / `已审批` / 类型：`普通`
- `rejected` / `已拒绝` / 类型：`结束`

流转规则：

- `pending` -> `approved` / 操作名称：`审批通过`
- `pending` -> `rejected` / 操作名称：`驳回`

## 注意事项

- 如果没有填写 `标题字段`，创建流程时会校验失败。
- `初始状态` 必须与状态区块中的某个 `状态标识` 完全一致。
- 工作流定义保存后，需确认业务数据是否已经绑定对应表名，并且调用 `startInstance` 启动流程实例后，才能在订单列表或流程实例页看到流程状态。

## 🚀 配置工作流的步骤

### 步骤1：创建工作流定义

访问：`/admin/workflow/add`

**必填字段**：

- **工作流名称**：如"订单审批流程"
- **工作流标识**：如`order_approval`（英文，唯一）
- **关联表名**：选择`mes_order`（MES订单表）
- **标题字段**：选择`order_no`或`order_name`（用于显示流程标题）

### 步骤2：定义流程状态

在"流程状态"区域添加状态：

**示例状态配置**：


| 状态标识       | 状态名称 | 类型  | 排序  |
| ---------- | ---- | --- | --- |
| `draft`    | 草稿   | 开始  | 1   |
| `pending`  | 待审核  | 普通  | 2   |
| `approved` | 已通过  | 结束  | 3   |
| `rejected` | 已拒绝  | 结束  | 4   |


### 步骤3：设置流转规则

定义状态之间的转换关系：

**示例流转配置**：


| 从状态 | 到状态 | 转换名称 | 是否需要审批 |
| --- | --- | ---- | ------ |
| 草稿  | 待审核 | 提交审核 | 是      |
| 待审核 | 已通过 | 通过   | 是      |
| 待审核 | 已拒绝 | 拒绝   | 是      |
| 已拒绝 | 草稿  | 重新编辑 | 否      |


### 步骤4：配置审批人

为需要审批的流转节点设置审批人：

- **指定用户**：选择具体的审批人员
- **角色审批**：按角色审批（如"管理员"角色）
- **部门审批**：按部门审批

## 🔄 实际使用流程

### 场景：MES订单审批

#### 1. 创建订单

- 工人在MES中创建生产订单
- 订单自动进入"草稿"状态

#### 2. 提交审核

- 订单创建者点击"提交审核"
- 订单状态变为"待审核"
- 系统通知审批人

#### 3. 审批处理

- 审批人登录后台查看待审批订单
- 可以选择"通过"或"拒绝"
- 填写审批意见

#### 4. 流程结束

- 通过：订单进入"已通过"状态，可以开始生产
- 拒绝：订单进入"已拒绝"状态，可重新编辑

## 💡 使用建议

1. **先执行SQL文件**：系统在 `database/migrate_workflow_system.sql` 中预置了"订单审批流程"示例，但需要先执行该SQL文件才能在后台看到
2. **手动创建工作流**：如果SQL文件未执行，需要手动按照文档说明创建工作流
3. **按需调整**：根据实际业务需求调整状态和流转规则
4. **简化流程**：初期可以设置简单的"草稿→审核→完成"流程
5. **权限控制**：确保审批人有相应的权限

## 📋 执行预置SQL文件

如果后台工作流列表为空，需要执行以下SQL文件来创建预置的"订单审批流程"：

```bash
# 在项目根目录执行
mysql -u数据库用户名 -p数据库名 < database/migrate_workflow_system.sql
```

**示例**：

```bash
mysql -uroot -p thinkmes < database/migrate_workflow_system.sql
```

执行成功后，后台工作流列表中会显示"订单审批流程"，包含：

- 工作流名称：订单审批流程
- 工作流标识：order_approval
- 关联表名：mes_order
- 预置状态：草稿、待审核、已通过、已拒绝
- 预置流转：提交审核、通过、拒绝、重新编辑

## ⚠️ 注意事项

- 工作流标识必须唯一
- 删除工作流会清除相关的实例数据
- 已完成的流程不能再次流转
- 审批人必须对业务表有访问权限
- 如果没有填写 `标题字段`，创建流程时会校验失败
- `初始状态` 必须与状态区块中的某个 `状态标识` 完全一致
- 工作流定义保存后，需确认业务数据是否已经绑定对应表名，并且调用 `startInstance` 启动流程实例后，才能在订单列表或流程实例页看到流程状态

## 后续操作提示

1. 在 MES 订单列表页查看 `流程状态`。
2. 如果订单尚未启动工作流，则会显示 `未启动`。
3. 点击订单详情或工序进度页，可查看流程实例和审批记录。
