# 基础框架打包说明

基础框架为**仅后台底座**的可发布包，不包含 MES、CRM、AI、设备、人事、财务、支付等业务应用；业务应用通过「应用中心 → 上传应用包」单独安装。

**打包与安装**：以 **build/pack_base.php** 为准（与 build 一致）。用户解压后访问 **/install**，按向导**分步安装**（环境检测 → 填写数据库 → 设置管理员 → 执行安装），无需手动改 .env 或导入 SQL。

---

## 一、打包方式（以 build 为准）

在项目根目录执行：

```bash
composer install   # 若未安装依赖
php build/pack_base.php [版本号]
```

- 版本号可选，默认 `1.0`。
- 产出：**dist/thinkmes-base-{版本}.zip**（发布用）。打包过程会先复制到 **build/output/thinkmes-base/**，再打成 zip，该目录为临时副本，不会进入 zip 内。

---

## 二、用户安装流程（与 build 一致）

1. 解压 zip，将**网站运行目录**指向解压后的 **public** 目录。
2. 若包内未带 vendor 或需更新依赖，在项目根目录执行 **composer install**（与 app、public 同级）。*pack_base 打出的包已含 vendor，一般可直接安装。*
3. 浏览器访问：**http://你的域名/install**
4. 按向导步骤：
   - **步骤一**：同意安装协议
   - **步骤二**：环境检测（PHP 扩展、目录可写）
   - **步骤三**：填写数据库（主机、端口、库名、用户名、密码、表前缀）
   - **步骤四**：设置超级管理员账号与密码
   - **步骤五**：确认并执行安装
5. 安装成功后使用页面提示的**随机后台地址**登录（安装程序会生成随机入口并写入 .env）。

## 三、基础框架包含内容

| 类型 | 说明 |
|------|------|
| **控制器** | Index、Admin、Role、AuthRule、Config、Log、Attachment、Tenant、TenantPackage、TenantPackageFeature、TenantOrder、TenantMiniapp、AppCenter、Member、Profile、Common、Backend、Addon、Backup、Notification、Workflow、CustomField、Export、Report、Api、PrintTemplate、SmsConfig 等（系统底座与扩展入口） |
| **路由** | 仅 `app/admin/route/app.php` 中底座路由；**不包含** mes/crm/ai/payment/equipment/hr/finance 的独立路由文件 |

| **多语言** | **后台**：`app/admin/lang` 含 `zh-cn`、`en`、`ko`（Backend、Index、各控制器语言包）；**前端**：`app/index/lang` 含 `zh-cn.php` / `en.php` / `ko.php` 及 `zh-cn/`、`en-us/`、`ko/` 控制器语言包。配置见 `config/lang.php`（默认 zh-cn，允许 zh-cn/en/en-us/ko） |

## 四、打包时排除内容

脚本会从副本中**删除**以下内容后再打 zip。

### 3.1 后台控制器与模型、视图

- **控制器目录**：`app/admin/controller/{mes,crm,ai,payment,equipment,hr,finance}`  
- **单文件**：`app/admin/controller/AiPackage.php`  
- **模型目录**：`app/admin/model/{mes,crm,payment,equipment,hr,finance}` 及 `model/ai`（若存在）  
- **视图目录**：`app/admin/view/{mes,crm,ai,payment,equipment,hr,finance}`  

### 3.2 路由与 API

- **路由文件**：`app/admin/route/mes.php`、`crm.php`、`ai.php`、`payment.php`、`equipment.php`、`hr.php`、`finance.php`  
- **API 控制器**：`app/api/controller/Cockpit.php`、`Scanwork.php`、`Payment.php`、`Ai.php`、`Customer.php`、`Worker.php`  

### 3.3 数据库

- **迁移**：`migrate_add_mes_*`、`migrate_add_crm_*`、`migrate_crm_*`、`migrate_add_customer_portal`、`migrate_add_ai_*`、`migrate_add_payment_*`、`migrate_equipment.sql`、`migrate_hr.sql`、`migrate_finance.sql`  
- **种子**：`seed_mes_*`、`seed_crm_*`、`seed_ai_*`、`seed_payment_*`、`seed_equipment_*`、`seed_hr_*`、`seed_finance_*`、`seed_menu_full_saas_factory.sql`  

### 3.4 复制阶段即排除的目录

- `.git`、`runtime`、`vendor`、`node_modules`、`.env`、`*.zip`、`public/uploads`、`build`、`dist`

## 五、基础版与完整版隔离（不改动仓库）

- **原则**：仓库以**完整版**为准；基础版差异只放在 **build/** 下，打包时覆盖到副本，**不修改** `app/`、`config/`、`database/` 等仓库文件，避免「改基础版把完整版也改坏」。
- **init.sql**：  
  - 仓库 **database/init.sql**：保留完整版逻辑（如预置租户套餐种子），供完整版安装使用。  
  - **build/database/init_base.sql**：基础版专用，表结构一致但**不预置租户套餐**，由部署方在后台「租户套餐」自行添加。  
- **pack_base.php** 打包时：若存在 `build/database/init_base.sql`，则用其作为副本里的 `database/init.sql`；否则用仓库的 `database/init.sql`。  
- 其他基础版专用文件（如底座路由）已采用同样方式：`build/admin_route_base.php`、`build/index_route_base.php`、`build/api_route_base.php` 在打包时覆盖到副本。

## 六、安装与 database

- **安装向导**仅执行 **database/init.sql**（表前缀由用户在步骤三填写，安装时自动替换）。  
- 基础版 zip 内的 init.sql 来自 **build/database/init_base.sql**，含完整底座表与初始管理员/角色/菜单，**不预置租户套餐**。  
- 打包后 zip 内仅含 init.sql（及安装说明等）；**首次安装只需通过 /install 完成，无需手动导入**。  

---

## 七、与应用包的关系

- 基础包：仅框架，应用中心列表为空（或仅显示后续通过上传安装的应用）。  
- 各业务应用按 `docs/应用包制作与发布.md` 打成独立 zip，在后台「应用中心」上传安装；安装后会自动合并路由、执行 SQL、写入 config 并在菜单中显示。
