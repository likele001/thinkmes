# 模块与应用中心对照

## 一、发布策略

- **基础打包**：仅后台框架（多租户、套餐、权限、日志、附件、应用中心等），**开源发布**，不包含任何业务应用代码。
- **各业务应用**：**单独打包发布**（如 MES、CRM、AI、设备、人事、财务等），通过应用中心「上传应用包」安装到基础框架上。

---

## 二、基础框架包含内容

- **控制器**：Index、Admin、Role、AuthRule、Config、Log、Attachment、Tenant、TenantPackage、TenantPackageFeature、TenantOrder、AppCenter、Member、Profile 等（系统底座）。
- **应用中心**：仅支持「上传 zip 应用包」安装；**不内置** mes/crm/ai 等应用列表，安装后的应用从 config 读取并展示。
- **路由**：仅底座与应用中心相关路由；各业务应用的路由随应用包解压合并到 `app/admin/route/`。

---

## 三、应用包格式（单独发布时）

每个应用单独打成一个 **zip**，根目录含：

- **app.json**（必填），示例：
```json
{
  "key": "mes",
  "title": "MES 制造执行系统",
  "description": "订单、报工、库存、质检等",
  "auth_prefix": "mes",
  "check_table": "mes_product",
  "sql_files": [
    "migrate_add_mes_tables.sql",
    "migrate_add_mes_extended_tables.sql",
    "seed_mes_menu.sql"
  ]
}
```
- **app/**：控制器、模型等，合并到项目 `app/`。
- **public/**（可选）：静态资源，合并到 `public/`。
- **database/**：迁移与菜单 SQL，合并到 `database/`；`sql_files` 中列出的文件须在此目录存在。

上传后框架会解压合并并执行 `sql_files`，写入 `app_xxx_installed` 与菜单显示前缀 `auth_prefix`。

---

## 四、应用中心逻辑（基础版）

| 能力 | 说明 |
|------|------|
| **应用列表** | 只显示「已安装的应用」（config 中 `app_*_installed=1`），标题/描述来自安装时写入的 `app_*_title`、`app_*_description`。 |
| **安装** | 仅支持「上传应用包」；基础版不提供「内置应用一键安装」。 |
| **卸载** | 对已安装应用可卸载：菜单隐藏（按 config 中 `app_*_auth_prefix`），`app_*_installed=0`，数据表不删。 |

---

## 五、可选：带内置应用的发行版

若某发行版希望内置部分应用（如演示版、企业版），可在同一套代码中：

- 在 `AppCenter::initialize()` 里再次填充 `$this->apps`（mes/crm/ai 等），并保留原有 `install()` 逻辑；
- 应用列表会同时展示「已安装」与「未安装的内置应用」，未安装的可一键安装。

基础开源版保持 `$this->apps = []`，不内置任何应用。
