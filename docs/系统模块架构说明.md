# 系统模块架构说明

## 1. 文档信息

- 系统名称：ThinkMES 多模块管理平台（KeleAdmin 后台）
- 适用范围：后台管理端（`app/admin`）为主，覆盖 API 与前台协同
- 技术栈：ThinkPHP8 + ThinkORM + MySQL + Pear Admin/Layui + jQuery/Bootstrap
- 文档用途：用于研发协作、实施交付、管理汇报、模块接入对齐

## 2. 系统总体架构

### 2.1 架构分层

系统采用典型分层模式：

1. 表现层（View + JS）
2. 路由层（Route）
3. 应用层（Controller）
4. 领域服务层（Service）
5. 数据层（Model + DB）
6. 基础设施层（中间件、权限、租户、日志、配置）

主调用链：

`HTTP Request -> Route -> Middleware -> Controller -> Service -> Model/DB -> View/JSON`

### 2.2 顶层目录说明

- `app/admin`：后台管理（核心）
- `app/api`：API 接口层（小程序/外部系统）
- `app/index`：前台与用户中心
- `app/common`：公共服务、中间件、通用库
- `database`：初始化、迁移、种子脚本
- `public/assets`：前端静态资源与后台 JS
- `build`：打包产物与基线初始化 SQL

## 3. 后台 admin 分层结构

### 3.1 路由层（Route）

- 路由聚合文件：`app/admin/route/app.php`
- 模块路由按文件拆分并按需加载：
  - `app/admin/route/mes.php`
  - `app/admin/route/crm.php`
  - `app/admin/route/hr.php`
  - `app/admin/route/finance.php`
  - `app/admin/route/equipment.php`
  - `app/admin/route/payment.php`
  - `app/admin/route/workflow.php`
  - `app/admin/route/extension.php`

### 3.2 控制器层（Controller）

- 基类：`app/admin/controller/Backend.php`
- 平台控制器：`Admin.php`、`Role.php`、`AuthRule.php`、`Tenant.php`、`AppCenter.php`
- 业务控制器按子目录拆分：
  - `app/admin/controller/mes/*`
  - `app/admin/controller/crm/*`
  - `app/admin/controller/hr/*`
  - `app/admin/controller/finance/*`
  - `app/admin/controller/workflow/*`

### 3.3 模型层（Model）

- 平台与业务模型：`app/admin/model/*`
- 分域模型：`app/admin/model/mes/*`、`crm/*`、`hr/*`、`workflow/*`
- 统一工作流模型：`app/admin/model/workflow/DefinitionModel.php`、`TaskModel.php`、`InstanceModel.php`、`LogModel.php`

### 3.4 视图层（View）

- 主布局：`app/admin/view/layout/default.html`
- 公共脚本：`app/admin/view/common/script.html`
- 模块页面：`app/admin/view/mes/*`、`crm/*`、`hr/*`、`workflow/*` 等
- 后台品牌与布局风格：KeleAdmin 标识 + Pear Admin 结构

### 3.5 服务层（Service）

- 公共服务：`app/common/service/*`
- 工作流标准引擎：`app/common/service/workflow/WorkflowEngine.php`
- 通知与超时：`WorkflowNotificationService.php`、`WorkflowTimeoutService.php`

## 4. 核心业务模块说明

### 4.1 平台底座模块（权限、租户、应用）

- 职责：账号、角色、权限、租户、套餐、订单、插件、应用中心
- 关键路由：`tenant/*`、`role/*`、`auth_rule/*`、`app_center/*`
- 价值：为所有业务模块提供统一治理能力

### 4.2 MES 制造执行模块

- 关键路由：`app/admin/route/mes.php`
- 职责：订单、生产计划、排程、工序、库存、采购、质检、BI
- 目录参考：`app/admin/controller/mes/*`、`app/admin/view/mes/*`

### 4.3 CRM 客户关系模块

- 关键路由：`app/admin/route/crm.php`
- 职责：客户、联系人、商机、销售订单、跟进、回款
- 特点：与 MES 存在业务协同（销售到生产）

### 4.4 HR 人力资源模块

- 关键路由：`app/admin/route/hr.php`
- 职责：组织、员工、考勤、请假、加班
- 示例模型：`app/admin/model/hr/HrEmployeeModel.php`

### 4.5 财务模块

- 关键路由：`app/admin/route/finance.php`
- 职责：收付款、应收应付、利润与经营数据分析

### 4.6 设备管理模块

- 关键路由：`app/admin/route/equipment.php`
- 职责：设备档案、保养、维修、运行记录、点检

### 4.7 客服中心模块

- 关键入口：`app/admin/route/app.php` 内 `customer_service/*`
- 职责：会话、工单、知识库、FAQ、分类、AI 历史、配置

### 4.8 AI 与内容生产模块

- 关键路由：`app/admin/route/ai.php`、`app/admin/route/prompt.php`
- 职责：AI 配置、生成任务、配额管理、内容流程辅助

### 4.9 支付与扩展模块

- 支付：`app/admin/route/payment.php`
- 扩展：`app/admin/route/extension.php`、应用中心安装卸载
- 职责：模块化能力扩展与商业化支撑

### 4.10 工作流标准模块（统一 `wf_*`）

- 统一路由：`app/admin/route/workflow.php`
- 统一控制器：`app/admin/controller/workflow/*`
- 统一模型：`app/admin/model/workflow/*`
- 统一引擎：`app/common/service/workflow/WorkflowEngine.php`
- 当前约束：新增与存量流程运维均以 `fa_wf_*` 为唯一数据口径
- 团队执行清单：见 `docs/工作流统一改造路线图.md` 第 11 节（PR 检查项、禁用名单、`scripts/pre_release_wf_check.sh`）

## 5. 跨模块通用能力

### 5.1 权限治理

- 核心：RBAC（管理员、角色、权限规则）
- 关键实现：`app/common/lib/Auth.php` + 权限中间件

### 5.2 多租户隔离

- 租户识别与上下文：`app/common/middleware/TenantResolve.php`
- 写入保护与资源约束：`TenantWriteGuard.php`、`TenantResourceCheck.php`

### 5.3 菜单与功能开关

- 菜单与权限种子：`database/seed_*_menu.sql`
- 模块可按路由文件和菜单规则进行安装与启用

### 5.4 通知与审计

- 平台通知：基于后台公共机制
- 工作流通知：`WorkflowNotificationService.php`
- 操作审计：日志模块 + 流程日志

## 6. 数据库与迁移策略

### 6.1 脚本分类

- 初始化：`database/init.sql`
- 模块迁移：`database/migrate_*.sql`
- 菜单与权限种子：`database/seed_*.sql`
- 工作流现行标准：`migrate_wf_engine_linear.sql`（`fa_wf_*` 表族）

### 6.2 演进特点

- 采用增量迁移方式支持模块逐步上线
- 工作流能力已统一为 `wf_*` 引擎，历史脚本仅作归档参考

## 7. 当前架构现状评估

### 7.1 优势

- 模块拆分清晰，适合多行业并行扩展
- 路由分片 + 菜单种子，具备应用化交付能力
- 租户与权限底座相对完整

### 7.2 风险

- 历史备份文件（如 `*_old.php.bak`）可能造成认知干扰
- 模块迁移脚本多版本并行，升级路径复杂度较高

## 8. 术语与缩写

- RBAC：Role-Based Access Control，基于角色的权限控制
- MES：Manufacturing Execution System，制造执行系统
- CRM：Customer Relationship Management，客户关系管理
- WF：Workflow，工作流引擎能力

## 9. 后续维护建议

1. 持续执行“工作流仅 `wf_*`”准入规则并沉淀接入规范
2. 治理历史路由和备份代码，减少双入口
3. 建立数据库迁移台账（版本、环境、执行记录）
4. 为关键跨模块流程补齐回归用例与对账机制
